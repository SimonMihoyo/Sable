## 一、架构概述

### 1.1 系统定位

面向中小企业的数据安全合规 SaaS 平台，提供数据资产发现、分类分级、访问审计、合规评估一站式管理能力。

### 1.2 架构目标

| 目标 | 指标 | 设计策略 |
|------|------|---------|
| 多租户隔离 | 租户间数据零泄漏 | Schema级隔离 + RLS兜底 |
| 高可用 | 99.9% SLA | 无状态应用层 + 主从数据库 |
| 弹性扩展 | 支持100+租户 | 应用层水平扩展 + 读写分离 |
| 审计性能 | ≥5000条/秒写入 | 异步队列 + 批量写入 + 分区表 |
| 安全合规 | 系统自身满足等保要求 | 全链路加密 + 操作审计 + 哈希链 |
| 可观测性 | 问题5分钟内定位 | 结构化日志 + 链路追踪 + 指标监控 |

### 1.3 架构原则

| 原则 | 说明 |
|------|------|
| 分层解耦 | 表现层、业务层、数据层严格分离 |
| 无状态设计 | 应用层不存储会话状态，支持水平扩缩 |
| 异步优先 | 非实时操作（审计写入、报告生成、扫描任务）全部异步化 |
| 配置外置 | 运行时配置通过配置中心管理，不打包在制品中 |
| 安全纵深 | 每一层都有独立的安全措施，不依赖单一防线 |
| 可观测 | 日志、指标、链路追踪三件套从第一天就接入 |

## 四、详细架构设计

### 4.1 应用架构（单体分模块）

MVP阶段采用**模块化单体**架构（Modulith），不走微服务。理由：

| 考量 | 说明 |
|------|------|
| 团队规模 | 3-5人，微服务运维成本过高 |
| 业务边界 | 模块边界清晰但数据高度共享 |
| 部署复杂度 | 单体一次部署，降低运维负担 |
| 演进路径 | 模块间通过接口隔离，未来可拆 |

```
sable-compliance/
├── sable-gateway/              ← API网关模块
├── sable-common/               ← 公共模块（工具类、异常、DTO基类）
│   ├── sable-common-core/
│   ├── sable-common-redis/
│   ├── sable-common-mybatis/
│   └── sable-common-security/
├── sable-system/               ← 系统管理模块（用户、角色、租户、配置）
├── sable-discovery/            ← 数据资产发现模块
├── sable-classify/             ← 分类分级模块
├── sable-audit/                ← 审计引擎模块
├── sable-assessment/           ← 合规评估模块
├── sable-alert/                ← 告警引擎模块
├── sable-report/               ← 报告引擎模块
├── sable-sdk/                  ← 客户端审计采集SDK
└── sable-admin/                ← 管理后台（前端）
```

**模块间通信：**

```
同步调用：模块间通过 Spring Bean 直接调用（同进程）
         通过接口(interface)隔离，禁止跨模块直接依赖实现类

异步通信：审计事件、告警通知等通过 RabbitMQ 解耦

数据隔离：每个模块独立数据库Schema，通过接口访问，不直接查对方的表
```

**租户上下文传递链路：**

```
HTTP Request
    │
    ▼
Gateway: 解析JWT → 提取tenantId → 写入请求头 X-Tenant-Id
    │
    ▼
TenantFilter: 读取X-Tenant-Id → 写入ThreadLocal(TenantContext)
    │
    ▼
MyBatis Interceptor: 读取TenantContext → SET search_path TO tenant_{id}
    │
    ▼
PostgreSQL: 在对应租户Schema中执行SQL
```

    // 测试连通性
    boolean testConnection(DataSourceConfig config);

// 新增数据源类型只需实现接口 + 注册为Spring Bean
@Component
public class MysqlDataSourceScanner implements DataSourceScanner {
    @Override
    public String getType() { return "MYSQL"; }

    @Override

        // JDBC metadata 扫描逻辑
    }
}

## 九、容灾与高可用

### 9.1 各层容灾设计

| 层级 | 故障场景 | 应对策略 | 恢复时间 |
|------|---------|---------|---------|
| 接入层 | 单Nginx节点宕机 | SLB健康检查自动摘除 | < 30s |
| 应用层 | 单Pod OOM | K8s自动重启 + HPA扩容 | < 60s |
| 数据库 | 主库宕机 | 自动切换至从库（RDS高可用） | < 30s |
| 缓存 | Redis节点宕机 | Sentinel自动故障转移 | < 10s |
| 消息队列 | RabbitMQ节点宕机 | 镜像队列自动切换 | < 30s |
| 搜索 | ES节点宕机 | 副本分片自动接管 | < 60s |
| 存储 | MinIO节点宕机 | 多副本冗余 | < 30s |

### 9.2 降级策略

| 场景 | 降级方案 |
|------|---------|
| ES不可用 | 审计日志降级写入PostgreSQL（性能降低但功能可用） |
| RabbitMQ不可用 | SDK本地缓存审计事件，恢复后补发 |
| Redis不可用 | 降级为数据库会话（性能降低但功能可用） |
| 数据源不可达 | 扫描任务标记失败，不影响其他数据源 |
| 报告生成超时 | 异步生成 + 完成后通知，不阻塞请求 |

### 10.2 技术债务管理

| 债务项 | 说明 | 还债时机 |
|--------|------|---------|
| 单体部署 | MVP阶段不做微服务拆分 | 租户数 > 50 或性能瓶颈出现 |
| 审计日志双写 | PG + ES 双写，可能不一致 | Phase 2 引入CDC (Change Data Capture) |
| 规则引擎硬编码 | 初期部分规则硬编码 | Phase 2 全部迁移至LiteFlow |
| 报告模板 | 初期代码中定义模板 | Phase 2 迁移至数据库可配置 |
